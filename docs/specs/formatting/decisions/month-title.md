# Decisions: formatting/month-title

- Q-1 What does this spec cover, and what is its id? → The month title only, in one preconfigured date formatter. Other date outputs (day, short date, date and time), parsing date strings and amount formatting go to the feature index's Later list; the id stays `formatting/month-title`. The title's first character is capitalized so the formatter, not the screen, produces the approved "Październik 2026". Shapes: Goal, Scope, Data, BR-2, BR-3, Later. (create-spec, 2026-11-01)
- Q-2 Where does the money value type live, and how are amounts formatted? → `Money` stays in DataKit; UtilitiesKit formats primitives (a `Decimal` and an ISO 4217 code) when a screen needs it, so it adds no dependency and keeps its no-domain-types rule. Moving `Money` into UtilitiesKit is not planned: it would break the Foundation-only imports and the domain-agnostic rule, couple a public SemVer package to app data and invert spec dependencies. Shapes: Scope › Out, BR-7, Later. (create-spec, 2026-11-01)
- Q-3 Does the formatter decode several date string formats? → No: the title is static text, no form needs text date input yet, free-form parsing risks silently misreading a day for a month, and the native `DatePicker` is the preferred input. The first form that needs text date input brings its own parsing spec. Shapes: Scope › Out, Later. (create-spec, 2026-11-01)
- Q-4 What shape and name does the formatter have? → A value type configured once, `DisplayDateFormatter`, not a per-date `DateText` value; `DateFormatter` is Foundation's. The name says user-facing display text and can grow to other outputs without renaming a public type. Shapes: Goal, Data, BR-1. (create-spec, 2026-11-01)
- Q-5 Which components and method signature? → `monthTitle(year: Int, month: Int) -> String?`: both values required, named after what it returns. `stringFrom(year:month:)` with optional `Int` defaults is not used: it is Objective-C style and gives `nil` components no defined meaning; day, hour and minute join with the first output that shows them. Shapes: Data, BR-2, BR-4, AC-7. (create-spec, 2026-11-01)
- Q-6 How are locale, calendar and time zone supplied, and what may code do with singletons? → Each init parameter defaults to `.autoupdatingCurrent` as the fallback, while Core passes the injected values. A singleton may be passed as an argument or default a parameter or property (`DisplayDateFormatter(locale: .autoupdatingCurrent)`, `private let locale: Locale = .current`); calling members on it stays prohibited (`Locale.current.currencySymbol(...)`). The root rule, the UtilitiesKit rule and `no_singletons` are reworded to match, and `injected_time_and_locale` becomes `injected_clock` checking only `Date()`. Shapes: Data, BR-1, BR-5, BR-8, AC-6, AC-8, AC-11, AC-12. (create-spec, 2026-11-01)
