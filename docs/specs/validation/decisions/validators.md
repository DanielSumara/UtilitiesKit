# Decisions: validation/validators

- Q-1 Which locale does a validator or rule use? → No validation call takes a `Locale`: `reason(for:)`, `force()` and a validator take none. A rule that needs one, e.g. to parse or format a number, takes it once when the form builds it, as a parameter defaulting to `.autoupdatingCurrent`; it never selects copy, which comes from `String(localized:)` in the form. This increment's rules need none. Shapes: Goal, US-4, Data, BR-9, BR-15, AC-8, AC-9, AC-13. (create-spec, 2026-10-31; amended in review round 1: locale at construction, defaulting to `.autoupdatingCurrent`; `String(localized:)` for copy)
- Q-2 Which FinanceTracker rules does this increment cover? → The core (`ValidationResult`, `ValidationRule`, `Validator` with focus), text rules (`required`, `length` range and at most) and composition (`allOf`, `ifPresent`). Comparisons, `parsed`, decimal places, amount, rate and account number arrive with the first spec that needs each. Shapes: Scope, Data. (create-spec, 2026-10-31)
