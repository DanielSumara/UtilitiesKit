# Decisions: testing/test-utilities

- Q-1 Where does the shared test kit live? → A second product, TestUtilitiesKit, in the public UtilitiesKit package, so UtilitiesKit's tests and every HomeBudgetApps test target use it. HomeBudgetApps TestKit keeps the domain fixtures. Shapes: Goal, Scope, BR-1. (create-spec, 2026-10-27)
- Q-2 How do tests cover Polish and English: test plan configurations reading the current locale, or test arguments? → Arguments: a language-dependent test runs over `TestLanguage.allCases` and injects the language's locale; expectations take that locale. The HomeBudgetApps test plan also runs in Polish and English (HomeBudgetApps shell/test-languages), so a test that reads the current locale fails in one of them. Shapes: Data, BR-2, BR-9. (create-spec, 2026-10-27) Superseded by Q-10.
- Q-3 What does an entry match on? → The locale's language code; region and script are ignored. The app replaces only the language (HomeBudgetApps shell/app-project BR-10). Shapes: BR-3. (create-spec, 2026-10-27)
- Q-4 Should `match` return its outcome? → No: it always returns `true` and records each failure with `Issue.record` at the expected value's line; returning `false` would make `#expect` record the same failure a second time. Shapes: BR-4. (create-spec, 2026-10-27)
- Q-5 What stays of the original files' comments and constants? → No project headers, doc comments or constants; `.albania` and `.unitedKingdom` become `.polish` and `.english`. The comment explaining `return true` stays, as one `// Workaround:` line. Shapes: BR-11. (create-spec, 2026-10-27)
- Q-6 Which locale does `TestLanguage.english` inject: `en_PL`, `en` or another? → `en_GB`, the user's choice over the proposed `en_PL`. Shapes: Data, BR-3, AC-1, AC-2, AC-9. (review-spec round 1, 2026-10-27)
- Q-7 Does Difference build under Swift 6 strict concurrency with no warnings? → Yes: its latest tag, 1.1.0, declares tools 5.3, so it builds in Swift 5 mode as a dependency with its warnings suppressed, and its `diff` is a generic free function with no global mutable state. Pinned to exactly 1.1.0. Shapes: BR-1, AC-10. (review-spec round 1, 2026-10-27)
- Q-8 Keep a separate `Optional.match`? → No: `Optional` is `Equatable` when its wrapped type is, so `Equatable.match` covers it and an entry may expect `nil`. BR-8 and AC-7 removed. Shapes: Scope, Data, AC-13. (review-spec round 1, 2026-10-27)
- Q-9 Should `match` take the locale, or the language the test runs in? → The language the test runs in: a recursive `TestScoping` trait, `testLanguages`, runs the body once per test language with a task-local `TestLanguage.current`; `match` checks only the entry for that language and skips the others, so `.polish(…)` alone asserts in the Polish pass only. Verified with a probe package: the trait reruns single tests, suite tests and each parameterized case per language. No test plan configuration per language. Supersedes Q-2 (arguments) and Q-3 (locale language code). The user's choice. Shapes: Goal, Scope, Data, BR-2, BR-3, BR-5, BR-6, AC-1, AC-2, AC-5, AC-14. (reopen, 2026-10-27) Superseded by Q-10.
- Q-10 How does a test get its language without passing a locale? → Test plan configurations: the plan runs every test in a Polish (`pl`, PL) and an English (`en`, GB) configuration, and `match`'s `locale` defaults to the process locale they set; entries match by language code (Q-3 again) and a missing language is an issue. Language-independent tests run twice, accepted. The trait, `TestLanguage.current` and AC-14 are dropped. The user's choice over `try #require(TestLanguage.current)` per test and a `TestLanguage.currentLocale` API. Supersedes Q-2 and Q-9. Shapes: Goal, Scope, Glossary, Data, BR-2, BR-3, BR-5, BR-6, AC-1, AC-2, AC-5, AC-15. (review-spec round 3, 2026-10-27)
- Q-11 How do UtilitiesKit's own tests, which `swift test` runs without a test plan, get both languages? → A Polish and English `UtilitiesKit.xctestplan` on the committed `UtilitiesKit-Package` scheme, run with `xcodebuild` instead of `swift test`, the user's choice over explicit `in:` locales in package tests. Shapes: Scope, BR-12, BR-13, AC-11, AC-15. (review-spec round 3, 2026-10-27)
- Q-12 Rename `LocaleMatch`? → `LanguageMatch`: entries are keyed by language, and no app test uses the type yet. Shapes: Scope, Glossary, Data, AC-9. (review-spec round 3, 2026-10-27)
- Q-13 The committed `UtilitiesKit-Package` scheme sits under `.swiftpm/`, which `.gitignore` ignores as a whole and the workspace `.claude/settings.json` denies reading: keep the test plan, or run `xcodebuild` twice with `-testLanguage`/`-testRegion`? → Keep the test plan, as the apps' `UnitTests.xctestplan` does, so ⌘U runs both languages into one result bundle; `.gitignore` re-includes `.swiftpm/xcode/xcshareddata/xcschemes/` level by level and the `Read(**/.swiftpm/**)` deny is narrowed to leave it readable. The user's choice. Shapes: BR-12, BR-13, AC-12. (review-spec round 4, 2026-10-27)
